# 🏆 Teste Backend

![Aiko](img/logo.png)

Esse teste é um convite para você mostrar como você trabalha.

Mais do que ver se você resolve um problema específico, queremos entender a sua forma de desenvolver: como você planeja, quais decisões toma no caminho e por quê, como lida com os problemas que aparecem e como explica o que construiu. Por isso ele é bem aberto, e você tem liberdade para escolher o que apresentar.

## 🎯 O que esperamos

No fim, são só duas coisas: um projeto de backend e um vídeo seu falando sobre esse projeto.

### Escolha um caminho

Qualquer uma dessas opções serve, e todas valem igual para nós:

1. **Seguir a nossa sugestão.** Preparamos uma sugestão de projeto (um refactoring kata) e já deixamos o código inicial dela na pasta [`sugestão/`](sugestão/). É um bom ponto de partida se você não tiver uma ideia própria na cabeça.

2. **Fazer um projeto do zero.** Se você tem uma ideia que representa melhor o seu trabalho fique a vontade para implementar. Escolhe o domínio, o tamanho, a linguagem, o framework e a arquitetura que você quiser.

3. **Mostrar um projeto que você já fez.** Você pode apresentar algum projeto (pessoal, de estudo, open source, o que for) que você curte e que mostra bem o que você sabe fazer. Nesse caso, use o vídeo para contar as decisões que você tomou enquanto desenvolvia.

Não tem linguagem, framework ou stack obrigatório. Use o que você domina ou o que fizer mais sentido para o projeto.

## 🎥 O vídeo (até 15 minutos)

O vídeo é a parte mais importante da entrega. Grave uma apresentação de no máximo 15 minutos contando como foi desenvolver o projeto. Não precisa ser nada produzido nem editado, queremos só acompanhar o seu raciocínio. Algumas coisas legais de comentar:

* Como você planejou antes de começar a codar e que plano acabou seguindo.
* Como o projeto foi tomando forma e quais foram os passos principais.
* O que foi difícil, o que você faria diferente e o que aprendeu no caminho.
* Quais tecnologias você usou, como usou e, principalmente, por que escolheu cada uma.

Fique à vontade para mostrar o código, rodar a aplicação, desenhar um diagrama, o que ajudar a contar a história do projeto.

## 🤖 Sobre usar IA

Pode usar IA à vontade, sem restrição nenhuma. Se faz parte do seu dia a dia, use normalmente.

O que interessa para nós é entender como você chegou no resultado. Se você usou IA, aproveite o vídeo para contar como foi esse trabalho em conjunto. Por exemplo: qual plano de implementação você montou (sozinho ou junto com a IA), em que momentos você direcionou, revisou ou corrigiu o que ela gerou, e como conferiu que o resultado ficou do jeito que você queria.

Usar IA não tira ponto. O que a gente olha é o seu critério e a forma como você conduz o desenvolvimento.

## 🔎 O que vamos olhar

* Como você pensa e organiza o trabalho.
* Por que você tomou as decisões que tomou (arquitetura, tecnologias, os trade-offs do caminho).
* A qualidade e a organização do código: se dá para ler, se está bem estruturado, se dá para testar.
* Como você explica tudo isso no vídeo.
* Se você usou IA, o quanto fica claro como você trabalhou com ela.

## 📦 Como entregar

1. Suba o código num repositório no GitHub.
2. Grave o vídeo (até 15 minutos). Dá para hospedar como não listado no YouTube, jogar no Google Drive, usar o Loom ou qualquer serviço parecido.
3. Mande os dois links para nós: o do repositório e o do vídeo. Se quiser, deixe o link do vídeo no README do seu repositório também, para ficar fácil de achar.

Uma dica: fazer commits com frequência e com boas mensagens ajuda a contar a história de como o projeto foi evoluindo, e combina bem com o vídeo.
